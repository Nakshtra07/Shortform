1. CURRENT FRAMING ARCHITECTURE
================================================================================

The active-speaker framing pipeline in autoShorts 3.0 consists of these stages:

STAGE 1: Diarization & Speaker Turns
- INPUT: Transcript words with Deepgram speaker labels (S1, S2, S3)
- `build_speaker_turns(words, clip_start, clip_end)` → contiguous speaking turns
- Each turn has (start_sec, end_sec, speaker_label)
- Speaker labels flow through pipeline but are NEVER used for visual face selection

STAGE 2: Shot Detection & Face Tracking
- `detect_scene_cuts(cap, sample_times_ms, start_ms)` → scene cut timestamps
- For each shot interval: `detect_faces(detector, frame)` → face detections
- `detect_faces()` uses FaceDetectorYN with:
  * conf >= FACE_CONF_THRESH (0.35) filter
  * size >= 15x15 filter
  * frontality calc: sym_err = |nose_x - mid_eye_x| / eye_dist; frontality = 1 - min(1, sym_err)
  * Back-of-head detection: conf < 0.75 AND (skin_ratio < 0.35 OR sym_err > 0.35) AND (bbox > 15000)
  * Mouth ROI extraction for motion analysis
- `track_faces_in_shot(shot_samples)` → builds temporal tracks within one camera shot
  * Tracks faces across frames using: cx, cy distance + mouth motion diff
  * Track state: cx, cy (smoothed), last_t, last_mouth, detections list
  * New track created when no existing track matches within 1.2s

STAGE 3: Shot Classification & Active Speaker Decision
- `classify_shot_and_find_speaker()` — THE CORE FUNCTION (lines 253-340)
- 4 code paths based on genuine face track count:
  * PATH A: Two-shot (len >= 2, horiz. sep > 160px) → mouth-motion discrimination
  * PATH B: Single-track (len == 1) → single face's cx used directly
  * PATH C: Pers_tracks (tracks exist but insufficient for two-shot) → conf*frontality selection
  * PATH D: No-face fallback → preserve last_confirmed_cx_by_spk[spk]

STAGE 4: Keyframe Generation & FFmpeg Expression
- `run()` orchestrates the full pipeline
- Generates keyframes = (timestamp, crop_x, is_hard_cut)
- `build_ffmpeg_expr(keyframes, clip_start, default_x)` → nested conditional expression
- 300ms smoothstep cubic easing for intra-shot transitions: s(u) = u²×(3-2u)
- Hard cut (0ms) on source camera cuts

STAGE 5: Rendering
- `render_flat_clip()` in media.rs → ffmpeg with vf crop.scale pipeline
- Uses crop filter: `crop=w:h:x:y` where x is from STAGE 4

3. WHY CLIPS FAIL — 3 CONCRETE FAILURE CASES
================================================================================

Based on the user's reference clips and the code analysis, here are 3 concrete failure
modes where the active speaker is lost:

FAILURE CASE 1: Camera Angle Change (Front → Side Profile)
- Speaker S1 is talking, front-facing view
- System tracks S1's face, cx ∈ [200, 300] (confirmed position)
- Camera angle shifts to side/profile
- Face detection still works but: face width changes, facial landmarks shift,
  sym_err (frontality) changes, mouth_gray availability changes
- CURRENT BEHAVIOR: The system interprets theseappearance changes as evidence
  the speaker has disappeared or changed. In PATH B (single-track), if the single
  face's cx_diff > 30px from last_confirmed, the position is preserved OR (if cx_diff
  > 80) the last confirmed is held. But the REAL problem is that the track itself
  may be disrupted because the matching distance metric (based on cx, cy + mouth diff)
  fails when the face orientation changes.
- OUTCOME: Crop jumps to wrong position or holds last confirmed during a shot where
  the new angle should still track the same speaker

FAILURE CASE 2: Speaker Switch with Simultaneous Faces
- Speaker A stops talking, Speaker B starts talking in the same shot
- Both faces may be visible briefly during the transition
- CURRENT BEHAVIOR: PATH A (two-shot) hardcodes S1→right_track, S2→left_track.
  When mouth motion discriminates which is speaking, the system switches framing
  but based on hardcoded positions. PATH B (single-track) if only one face remains,
  unconditionally overwrites last_confirmed_cx_by_spk[spk] with that face's cx,
  potentially grabbing the wrong person's face.
- OUTCOME: Crop either stays on previous speaker too long, or jumps to the wrong
  face when the transition occurs. No gradual transition - abrupt switch or freeze.

FAILURE CASE 3: Temporary Face Loss + Wrong Reacquisition
- Speaker stops talking, face disappears (encoder occlusion, hand to face, etc.)
- System holds last_confirmed_cx_by_spk[spk] via PATH D (no-face fallback) — this works
- BUT when face reappears: if a DIFFERENT face is detected first (e.g., the other
  person in a two-shot), and the system is in single-track mode, it may reacquire
  the WRONG face and permanently corrupt last_confirmed_cx_by_spk[spk]
- OUTCOME: Speaker returns but crop frames the wrong person/background; the original
  speaker's position is lost forever because last_confirmed was overwritten

================================================================================
4. ROOT CAUSE ANALYSIS
================================================================================

THE CORE PROBLEM: No Persistent Speaker Identity ↔ Face Track Mapping

The architecture has ZERO mechanism to link Deepgram speaker IDs (S1, S2, S3) to
visual face/track IDs. The pipeline flow is:

✅ Deepgram extracts speaker labels per word time range ✅
✅ build_speaker_turns() constructs turns from these labels ✅
✅ Labels passed as `spk` to classify_shot_and_find_speaker() ✅
❌ ❌ ❌ Face detection/tracking operates COMPLETELY INDEPENDENTLY of speaker labels
❌ ❌ ❌ No check whether the detected face corresponds to the labeled speaker
❌ ❌ ❌ last_confirmed_cx_by_spk[spk] overwritten based on visual features alone
❌ ❌ ❌ conf, frontality, back_ratio indicate detection QUALITY, not SPEAKER IDENTITY
❌ ❌ ❌ The system has NO memory of "which face was S1" across shots

This is why camera angle changes break everything: when the front-facing S1 face
turns to profile, the visual features (conf, frontality, back_ratio, cx, cy) all
change meaningfully. Without a persistent "this is S1's track" identifier, the
system has no choice but to treat the differently-looking face as either:
(a) A different person, or
(b) The same person but in a different state, with no way to know which

The current code's cx_diff thresholds (30/80px) are INSUFFICIENT because they only
compare horizontal position — they don't incorporate pose/identity information.

SECONDARY PROBLEM: Track Disruption on Pose Change

In track_faces_in_shot(), tracks are maintained using:
- Euclidean distance between (cx, cy) of new detection vs existing track
- Mouth motion diff (resized comparison)
- Track persistence: rel_t - tr["last_t"] > 1.2 → skip (discard)

When a speaker turns their head:
- cx, cy may shift slightly (head movement within the shot)
- mouth_gray availability may change (head orientation affects mouth visibility)
- The 1.2s maximum gap before track loss may be too short/or too long
- No pose-invariant matching mechanism exists

THIRD PROBLEM: The "Last Confirmed" Corruption Chain

The strict invariant from the code comments: "If the system cannot confidently
identify the active speaker, it must NOT invent a crop toward another person's face."

But thecurrent implementation:
- PATH B: Unconditionally overwrites last_confirmed_cx_by_spk[spk] with any single face
- PATH C: Overwrites based on conf*frontality (visual quality only)
- PATH A: Hardcodes S1→right, S2→left, then overwrites unconditionally

When any of these paths executes with the WRONG face (which happens when appearance
changes trigger track loss/re-acquisition), last_confirmed is permanently corrupted,
and ALL subsequent no-face shots (PATH D) fall back to this wrong position.

Add a persistent speaker identity state that is INDEPENDENT of individual face detections:

class SpeakerIdentity:
    """Persistent identity state for one speaker across the entire clip."""
    def __init__(self, spk):
        self.spk = spk  # diarization label: "S1", "S2", "S3"

        # Identity persisting across track losses, pose changes, camera cuts
        self.assigned_track_id = None  # Which track ID was last confirmed as this speaker
        self.track_creation_frame = None  # When this identity was first established

        # Spatial history — smoothed position, NOT replaced each shot
        self.position_history = []  # [(cx, cy, frame_idx), ...] maxlen = N
        self.position_index = 0  # Current position in history

        # Identity confirmation counters
        self.confirmed_frames = 0  # How many frames this identity has been confirmed
        self.min_confirm_frames = 5  # Minimum frames before identity is "confirmed"

        # Pose/state tracking
        self.last_known_pose = "front"  # front, side, three_quarter, profile
        self.pose_stability_counter = 0  # Frames with same pose classification

        # Temporary loss handling
        self.temporarily_lost = False  # Are we in a temporary loss state?
        self.loss_start_frame = None  # When loss began
        self.loss_max_frames = 15  # Max frames to hold position during loss (at fps ~8, ~2s)

        # Speaker change detection
        self.potential_switch_frame = None  # When a switch might be starting
        self.switch_evidence = 0  # Accumulated evidence for speaker change
        self.min_switch_evidence = 3  # Frames of evidence before a switch is accepted
```

This identity state survives:
- Track losses and recreation
- Pose changes (front → side → front)
- Temporary face disappearance
- Shot boundaries (with proper carry-over logic)
- Speaker switches (with evidence accumulation)

COMPONENT 2: TRACK-TO-IDENTITY ASSOCIATION
==========================================================================

Rather than treating each shot's tracks as Independent, maintain track-to-identity
association across the entire clip:

```python
# Global state: one entry per speaker identity
speaker_identities = {}  # "S1" → SpeakerIdentity, "S2" → SpeakerIdentity, etc.

# When a new track is detected in a frame:
def associate_track_with_identity(track, spk, frame_idx):
    """Associate a detected track with an existing speaker identity, or create new."""

    identity_key = spk

    if identity_key not in speaker_identities:
        # First time seeing this speaker — create identity state
        speaker_identities[identity_key] = SpeakerIdentity(spk)

    identity = speaker_identities[identity_key]

    # Check if this track is the same as the identity's assigned track
    if identity.assigned_track_id is not None:
        # Check if this track matches the assigned one
        if track["tid"] == identity.assigned_track_id:
            # Same track re-acquired — re-confirm identity
            identity.assigned_track_id = track["tid"]
            identity.track_creation_frame = frame_idx
            identity.temporarily_lost = False
            identity.confirmed_frames = min(identity.confirmed_frames + 1, 10)
            return "RE-ACQUIRED"

    # Check if this track's position is consistent with identity's position history
    if identity.position_history:
        recent_cx, recent_cy, recent_frame = identity.position_history[-1]
        cx_diff = abs(track["cx"] - recent_cx)
        cy_diff = abs(track["cy"] - recent_cy)

        if cx_diff < 50 and cy_diff < 50:  # Generous matching for pose changes
            # This track is in the same general area — likely the same speaker
            identity.assigned_track_id = track["tid"]
            identity.position_history.append((track["cx"], track["cy"], frame_idx))
            identity.pose_stability_counter = min(identity.pose_stability_counter + 1, 10)
            identity.temporarily_lost = False
            identity.confirmed_frames = min(identity.confirmed_frames + 1, 10)
            return "ASSOCIATED"

    # If identity has been confirmed and we've lost the track temporarily
    if identity.confirmed_frames >= identity.min_confirm_frames and identity.temporarily_lost:
        # We're in loss recovery — accept any track in the general area
        identity.assigned_track_id = track["tid"]
        identity.temporarily_lost = False
        identity.confirmed_frames = min(identity.confirmed_frames + 1, 10)
        identity.position_history.append((track["cx"], track["cy"], frame_idx))
        return "LOSS_RECOVERED"

    # New track but no strong association yet — tentatively associate if enough
    # positional evidence exists
    if identity.confirmed_frames >= identity.min_confirm_frames:
        # Identity is confirmed but track changed — this is a camera/speaker change
        # Don't forcibly reassign; let the switch detection handle it
        return "LIMITED_ASSOCIATION"

    # Unknown track — keep waiting
    return "UNKNOWN"
```

COMPONENT 4: POSE-ROBUST TRACK MATCHING
==========================================================================

Rather than matching tracks based solely on cx, cy distance, use pose-robust matching:

```python
def match_track_to_identity(track, identity, prev_track=None):
    """Match a track to a speaker identity using multiple cues."""

    scores = {}

    # CUE 1: Positional proximity (generous for pose changes)
    if identity.position_history:
        last_cx, last_cy, last_frame = identity.position_history[-1]
        cx_diff = abs(track["cx"] - last_cx)
        cy_diff = abs(track["cy"] - last_cy)
        scores["position"] = exp(-(cx_diff**2 + cy_diff**2) / 100)  # Gaussian decay
    else:
        scores["position"] = 0.5  # Neutral if no history

    # CUE 2: Mouth motion consistency
    if track.has_mouth_motion and identity.has_speaking_evidence:
        # Same direction of mouth motion → likely same speaker
        scores["mouth_motion"] = 1.0
    elif not track.has_mouth_motion and not identity.has_speaking_evidence:
        scores["mouth_motion"] = 0.8  # Both quiet, likely same
    else:
        scores["mouth_motion"] = 0.3  # Mismatch, lower score

    # CUE 3: Pose classification consistency
    current_pose = classify_pose(track)  # front, side, three_quarter, profile
    if identity.last_known_pose == current_pose:
        scores["pose"] = 1.0  # Same pose, strong evidence
    elif is_pose_transition(identity.last_known_pose, current_pose):
        scores["pose"] = 0.6  # Transitioning, moderate evidence
    else:
        scores["pose"] = 0.3  # Pose changed unexpectedly, lower evidence

    # CUE 4: Track persistence (age)
    track_age = frame_idx - track.creation_frame
    scores["age"] = min(track_age / 30.0, 1.0)  # Older tracks more reliable

    # Weighted composite
    total_score = sum(scores.values()) / len(scores)

    return total_score > 0.5  # Threshold for match
```

`classify_pose()` would classify based on facial landmarks:
- front: both eyes visible, face width normal
- side/three_quarter: one eye partially occluded, face narrower
- profile: one eye only, face narrowest

The key insight: a speaker whose face changes from front to side PROFILE is STILL
the same speaker. The pose classification + positional proximity + mouth motion
together provide robust matching that tolerates camera angle changes.

def detect_speaker_switch(current_identity, new_spk, new_track, frame_idx):
    """Detect and handle a speaker switch with proper transition logic."""

    # Check if the new diarized speaker is different from current
    if new_spk == current_identity.spk:
        return "CONTINUE"  # Same speaker, continue tracking

    # Accumulate evidence for a switch
    identity = speaker_identities[current_identity.spk]
    identity.switch_evidence = min(identity.switch_evidence + 1, 10)

    # Check: is the new speaker actually talking (mouth motion)?
    if new_track.has_speaking_evidence:
        identity.switch_evidence = min(identity.switch_evidence + 1, 10)
    else:
        # Other person quiet — might be listener reaction, not a switch
        # But if diarization says new speaker is talking, trust it
        if diarization_says_speaking(new_spk):
            scores["mouth_motion"] = 0.5  # Uncertain but proceeding

    # If enough evidence accumulated, accept the switch
    if identity.switch_evidence >= identity.min_switch_evidence:
        # Transition: hold previous speaker's position for N frames,
        # then gradually acquire new speaker
        identity.is_switching = True
        identity.switch_start_frame = frame_idx
        identity.switch_progress = 0
        identity.switch_frames_remaining = 10  # 10 frames ~ 1.25s transition
        return "SWITCH_INITIATED"

    # Not enough evidence yet — continue with current speaker
    return "INSUFFICIENT_EVIDENCE"
```

The switch transition logic in run() would then smoothly morph the crop from the

8. HANDLING CAMERA-ANGLE CHANGES
==========================================================================

The critical fix for camera angle robustness is in Components 1-4 above:

A. **Pose classification + history**: By classifying the pose (front/side/3/4/profile)
   and storing it in the identity state, the system recognizes that "front-facing S1
   turning to side profile" is the same speaker, not a new person.

B. **Positional proximity with generosity**: The track-to-identity association uses
   generous positional matching (50px cx/dy tolerance) specifically because pose changes
   can shift the face position. The Gaussian decay score function handles gradual shifts.

C. **Mouth motion as the ground truth**: When the face is talking (mouth motion > threshold),
   that's the strongest evidence we have that this is the same speaker regardless of pose.
   Even if the face is in profile, if the mouth is moving, it's the active speaker.

D. **Temporary loss state**: When the face temporarily disappears:
   - Enter `temporarily_lost = True` mode
   - Hold last known position for max_frames (15 frames ~ 2s at 8fps)
   - During this window, if a face re-appears in the general area, re-acquire
   - If no face re-appears, exit loss mode and hold center/last position
   - This prevents the "jump to another person" bug when face briefly occludes

E. **Pose transition tracking**: The pose_stability_counter and switch detection
   distinguish between:
   - "Speaker turned head slightly" → continue tracking same speaker
   - "Speaker turned head and another person now visible" → begin switch detection
   - "Camera cut to different angle" → carry identity state, re-acquire new speaker

The overall result: When the camera angle changes from front to profile, the system
recognizes the pose change, retains the speaker identity, and continues tracking the
speaker's position. The crop follows the speaker to the new position, rather than
jumping to background or another person.

9. HANDLING SPEAKER SWITCHING
==========================================================================

Speaker switching is handled by the combined switch detection + transition logic:

A. **Switch Initiation** (detect_speaker_switch()):
   - When diarization indicates a new speaker label
   - Accumulate evidence: is the new speaker talking (mouth motion)?
   - Is the old speaker still visible but quiet?
   - After min_switch_evidence frames (3 frames ~ 375ms at 8fps), initiate switch

B. **Transition Period** (run() keyframe generation):
   - During switch_frames_remaining (10 frames ~ 1.25s):
     * Frame N: crop at 80% old position + 20% new position
     * Frame N+1: crop at 60% old + 40% new
     * Frame N+2: crop at 40% old + 60% new
     * ...
     * Frame N+9: crop at 20% old + 80% new
     * Frame N+10+: fully on new speaker
   - This provides smooth movement rather than abrupt jump

C. **Switch Rejection** (to prevent false switches):
   - If the "new speaker" has no mouth motion for >5 frames, suspect listener reaction
   - Keep current speaker, reset switch evidence
   - If the pose of the "new speaker" matches the old speaker's typical pose,
     suspect it's the same speaker in a different position, not a switch

D. **Post-Switch Reconciliation**:
   - After the transition, the new speaker's identity becomes the active identity
   - The old speaker's identity is preserved in speaker_identities for potential
     return (e.g., if the original speaker resumes talking)
   - Position history for both is maintained

10. HANDLING TEMPORARY FACE LOSS
==========================================================================

When the active speaker's face temporarily disappears:

A. **Loss Detection**:
   - If no faces detected with conf >= FACE_CONF_THRESH for consecutive frames
   - OR if the identity's assigned_track_id is not found in current shot's tracks
   - Set `identity.temporarily_lost = True`
   - Record `identity.loss_start_frame = current_frame`

B. **Loss Holding Period**:
   - Maintain the last known position (from identity.position_history[-1])
   - Do NOT jump to another person's face (strict invariant)
   - After max_loss_frames (15 frames ~ 2s at 8fps), if face still not re-acquired:
     * Hold center position or last known position
     * Could gradually zoom out to show more background context

C. **Loss Recovery**:
   - If a face re-appears within max_loss_frames AND
     match_track_to_identity() returns True → re-acquire the speaker
   - Update identity.assigned_track_id, clear temporarily_lost flag
   - Continue tracking from the re-acquired position

D. **Loss Beyond Recovery**:
   - If face doesn't re-appear within max_loss_frames
   - The speaker is effectively "off-screen" for now
   - The crop holds the last known position or centers gently
   - When the speaker re-appears later (even after many frames), the identity
     state still exists and can re-acquire them

11. HANDLING SIDE PROFILES & POSE CHANGES
==========================================================================

The system must track speakers through front → side/profile → front transitions:

A. **Pose Classification** (classify_pose(track, landmarks)):
   ```python
   def classify_pose(track, landmarks):
       """Classify the face pose from facial landmarks."""
       re, le, nose, rm, lm = track["landmarks"]

       # Check eye visibility
       both_eyes_visible = (re[0] > 0 and le[0] > 0)  # Both eyes have x > 0
       one_eye_visible = (re[0] > 0) != (le[0] > 0)  # Exactly one eye visible
       no_eyes_visible = (re[0] <= 0 and le[0] <= 0)  # Neither eye visible

       # Check face width relative to image
       face_width = track["bbox"][2]  # fw from detection
       img_width = ...  # source frame width
       normalized_width = face_width / img_width

       if both_eyes_visible and normalized_width > 0.15:
           return "front"
       elif one_eye_visible and normalized_width > 0.10:
           return "three_quarter"
       elif not both_eyes_visible and normalized_width > 0.05:
           return "side"  # One eye visible, face in profile
       else:
           return "profile"  # Minimal face visible
   ```

B. **Pose-Robust Matching**: As described in Component 4, the matching scores
   combine positional proximity + mouth motion + pose consistency. A speaker whose
   pose changes from front to side still matches because:
   - Positional proximity: the body/head position in the frame may shift, but
     is within the generous tolerance
   - Mouth motion: if the speaker is talking, the mouth is moving → strong evidence
   - Pose consistency: the pose change itself is expected, so the transition
     score accounts for this

B. **No "Face Width = Different Person" Logic**: The system explicitly does NOT
   interpret changing face width as the speaker disappearing. The pose classification
   and matching scores tolerate the width change as a pose effect, not an identity change.

C. **Landmark-Based Tracking**: Using the 5 facial landmarks (re, le, nose, rm, lm)
   from FaceDetectorYN, the system can track feature points across frames even when
   the full face isn't visible. The distance between landmarks changes with pose, but
   the relative configuration remains stable for the same speaker.

12. ADAPTIVE ZOOM IMPLEMENTATION
==========================================================================

The adaptive zoom should create a professional portrait composition without pulsing:

A. **Base Crop Calculation**:
   - Each frame, compute desired crop based on speaker's visibility:
     * If face detection shows large face → medium zoom (speaker occupies ~50% of 9:16)
     * If face detection shows small face → zoom in (speaker occupies ~70% of 9:16)
     * If only upper face visible → zoom in tighter
     * If full body visible → zoom out for context

B. **Smooth Zoom Control**:
   - Track the desired zoom level across frames
   - Apply smoothing: `zoom_current = 0.8 * zoom_prev + 0.2 * zoom_desired`
   - Limit zoom change rate: max 0.5x change per second
   - This prevents pulsing while still adapting to speaker size changes

B. **Zoom Triggers**:
   - **Speaker moves closer**: zoom in smoothly over 2-3 seconds
   - **Speaker moves away**: zoom out smoothly over 2-3 seconds
   - **Camera cuts to tighter angle**: allow immediate zoom change (cut, not transition)
   - **Speaker raises arms/gestures**: maintain current zoom, don't cut off gestures

C. **Zoom Limits**:
   - Min zoom: speaker occupies ~40% of 9:16 frame (wide portrait)
   - Max zoom: speaker occupies ~80% of 9:16 frame (tight close-up)
   - These limits prevent extreme zooms that would cut off head or show too much background

D. **Interaction with Speaker Switch**:
   - During a speaker switch transition, freeze zoom changes (maintain previous zoom level)
   - After transition completes, resume adaptive zoom for the new speaker
   - This prevents the zoom from fighting the switch transition

14. WHY THE ORIGINAL SYSTEM FAILS — ROOT CAUSE SUMMARY
==========================================================================

The original system fails because it treats these as PROBLEMS when they're actually
NATURAL occurrences:

1. **Face width changing** (from front to side/profile) → NOT a problem, but system
   interprets it as the speaker changing → WRONG

2. **Facial landmarks changing** (different visibility in different poses) → NOT a
   problem, but system has no pose-invariant matching → WRONG

3. **Head orientation changing** → NOT a problem, but no poseTracking → WRONG

4. **Partial face visibility** (one eye occluded, etc.) → NOT a problem, but system
   has no occlusion handling → WRONG

5. **Temporary face disappearance** (occlusion, hand to face) → NATURAL, but system
   jumps to another person's face or corrupts last_confirmed → WRONG

6. **Speaker switching** → NATURAL, but system has abrupt jump or freeze, no smooth
   transition → WRONG

7. **Camera angle change** → NATURAL, but system has no pose robustness → WRONG

The common root: **NO PERSISTENT SPEAKER IDENTITY**. The system has only "last confirmed
cx position" which is fragile — one wrong face detection or pose change corrupts it,
and there's no mechanism to recover.

The fix requires building persistent speaker identity that survives all these natural
occurrences, with spatial tracking following the identity rather than the other way
around.
